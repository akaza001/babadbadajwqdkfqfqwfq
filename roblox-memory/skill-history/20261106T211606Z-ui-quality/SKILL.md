# Разработка игр Roblox

Отвечай на языке пользователя. Доводи порученную реализацию до проверяемого результата в проекте или Studio. Не выдавай дизайн-документ за собранную игру.

## Контекст и память

Корень постоянных данных: `/Users/andrej/Documents/ChatGPT/skills/roblox-memory/`. Сначала прочитай `index.md`, `chat-sources.json` и относящиеся к задаче записи проекта. Для доступа к истории и улучшений следуй [references/learning.md](references/learning.md). Разрешена только папка **Fight for eggs.**; новые источники добавляются по прямому указанию пользователя. Скилл задаёт область чтения, но не выдаёт системных разрешений и не работает в фоне.

## Перенос исправлений между играми

**Перед работой над любой новой игрой или правкой обязательно прочитай [references/regressions.md](references/regressions.md)** и выбери применимые случаи из встроенного реестра. Он содержит уроки Fight for eggs, поэтому они применяются даже когда текущий проект другой и его профиль ещё пуст. Используй выбранные случаи как критерии реализации и приёмки, а не как справку после возникновения бага. Подробные записи самой Fight for eggs читай только при работе над ней; её конкретные стиль и баланс не навязывай новым играм.

Явное общее указание пользователя из разрешённой истории: не управляй его ноутбуком через нативный UI/браузер без разрешения. Используй файловые инструменты и Studio MCP в рамках поручения; старое разовое согласие не даёт бессрочного разрешения на управление компьютером.

## Граф действий

Прочитай [references/graph.json](references/graph.json) и выбери узлы, нужные для задачи, вместе с их зависимостями `requires`. Не проходи весь граф для небольшой правки. `related` означает полезную связь, а не обязательный порядок. Человекочитаемый вид: [references/graph.md](references/graph.md). У каждого узла есть результат и способ проверки. Добавляй новые узлы при появлении повторно полезных зависимостей; проверяй уникальность ID, ссылки и отсутствие циклов в `requires` командой `python3 scripts/check_graph.py` из каталога скилла.

## Рабочий цикл

1. Установи цель, критерии готовности и фактическое устройство проекта. Проверь локальные AGENTS.md, имеющиеся модули, сцены, UI и тесты. Сохраняй согласованные параметры и стиль; не переделывай архитектуру ради отдельной правки.
2. Для Studio обнаружь актуальные инструменты Roblox Studio и вызови `list_roblox_studios`; выбери нужный экземпляр по имени и состоянию. При неоднозначности уточни выбор перед изменением. Соблюдай требования инструмента к подтверждению целевого проекта. Не используй сохранённые studio_id из старых чатов.
3. Разбей реализацию по выбранным узлам графа. Для новой механики сначала собери работающий небольшой срез: действие → серверный результат → UI → повторный запуск. Для визуальной правки проверь исходный объект и материал, затем исправляй причину.
4. При обращении к популярным играм прочитай [references/research.md](references/research.md) и нужные карточки библиотеки. Исследование уже сохранено; не загружай все 50 карточек при каждом багфиксе. Не называй предположенный способ реализации внутренним устройством чужой игры. Для выбора топологии карты, слоёв UI, раундов и анимационных состояний прочитай нужный раздел [references/visual-patterns.md](references/visual-patterns.md). Обзор покрывает все 50 позиций выборками видео, но не все карты, экраны и анимации; учитывай ограничения конкретной карточки.
5. Создавай оригинальные ассеты и Luau-модули. Практические рецепты и официальные источники: [references/implementation.md](references/implementation.md). Проверяй изменяемые API по Creator Hub перед использованием. Сервер принимает решения о наградах, предметах, уроне и сохранениях; клиент передаёт намерение и отображает результат.
6. Пройди применимые критерии из выбранных regression-cases; отмечай каждый как проверенный с наблюдением либо не проверенный с причиной. Текущий запрет пользователя на тесты имеет приоритет. Проверяй именно обещанное поведение: в Edit — устройство сцены, в Play — выполнение. Для визуальных изменений сравни изображения с одинаковой камерой; для анимаций наблюдай движение во времени, переходы и возрождение. Проверяй мобильную компоновку, если затронут UI. Снимок модели не доказывает работоспособность боя или сохранения.
7. Сохрани изменения в исходниках и соответствующих шаблонах/генераторах, если они существуют. Не исправляй только временный экземпляр, который будет пересоздан. Сообщи, что изменено, что проверено и что осталось непроверенным. Сохрани новые правки и полезные уроки в памяти.

Перед существенной заменой ассетов или модулей используй доступную обратимую копию/историю проекта; не удаляй чужие несвязанные изменения. Проверка не должна выдавать покупки или менять реальные профили игроков: используй тестовые данные. Публикация, загрузка платных ассетов и запуск платных сервисов требуют соответствующего поручения; создание скилла не является таким поручением.

## Саморазвитие

Пользователь разрешил накапливать правки и улучшать этот скилл во время работы. Явную поправку применяй в её области сразу; вывод из diff помечай гипотезой, пока причина не подтверждена. Предпочтения храни в профиле, игровые параметры — в проекте, универсальный проверенный приём — в инструкциях. Перед изменением инструкций сохрани предыдущие затронутые файлы и причину в общей памяти. Не меняй другие скиллы, разрешения, расписание и утверждённый дизайн по собственной инициативе.
