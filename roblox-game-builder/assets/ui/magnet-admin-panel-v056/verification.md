# Админ-панель и камера чистки 0.5.6

Запросы: создать админ-панель; приблизить камеру при чистке предмета. Реализованы в исходниках и подключены к Studio. Сохранено в Roblox Studio **163**, без публикации. Все64исходника local/Studio/XML совпадают, компиляция64/0ошибок,14RemoteEvents; временные QA-объекты удалены.

## Использование

Панель открывается **F4** или небольшой кнопкой **«Админ · F4»** под счётчиком монет. Доступ только аккаунту владельца<owner UserId>, подтверждённому через CreatorType.User/CreatorId и фактического LocalPlayer. Настройка хранится только на сервере в `src/server/AdminConfig.luau`. Режим Studio, DisplayName, клиентский actor/target и скрытая кнопка права не выдают. Управление действует только на собственный загруженный профиль администратора.

Светлая тема, поверхности и кнопки переиспользованы из WindowTheme/UI0.4.5. Кнопка администратора скрывается во время чистки и других действий, а также открытых игровых окон/результата; в закрытом состоянии центр игры свободен; при открытии скрываются игровой HUD/подсказки и блокируются обычные контекстные действия. Кнопки применяются по серверному результату; показаны текущие значения, ошибки и тестовый режим Studio. Большие формы и варианты прокручиваются, есть поиск команды и поиск предмета по имени/ID. Доступны повтор того же зависшего запроса, закрытие, F4 и Escape; при возрождении окно закрывается.

| Команда | Действие |

Журнал хранит последние60 результатов только в памяти текущего сервера; UI показывает20. Это не долговременный внешний журнал модерации. Бан/кик других игроков и несуществующие XP/питомцы/перерождения не добавлены. Все биомы остаются временно открыты, текущий баланс сохранён.

## Сервер и данные

AdminRegistry строит формы из текущего Config.items/BiomeCatalog и экземпляров своего профиля. Новый ID каталога появляется автоматически; новая характеристика требует регистрации серверного обработчика и описания, после чего клиент строит форму без отдельной кнопки. Клиент получает только разрешённые описания; функции остаются в ServerScriptService.

AdminService проверяет UserId на каждом запросе, типы/конечность/целочисленность/диапазоны, текущие ID/варианты, неизвестные поля и частоту. Нет произвольного Luau, пути к объекту, записи поля по строке или клиентского target. Запросы с nonce/монотонным seq;128результатов кешируются, старые seq отклоняются, в процессе одного сохранения повтор не запускает новую операцию. Профиль меняется через GameService.adminApply и штатный ProfileStore.commit/recentOperations. При ошибке успех не объявляется.

Удаление/сброс требуют второго действия внутри панели. Сервер выдаёт30-секундный одноразовый токен, связанный с точной командой и параметрами. На подтверждении указаны собственный профиль, область и последствия. Сброс сохраняет lease/revision/служебные даты/ledger, отменяет текущее действие, восстанавливает Tool/экспонаты/HUD; ожидающая фиксация награды/переход блокирует конфликтующую команду. Старый renew не восстанавливает прежние значения. В Studio используются только временные профили; в опубликованном сервере команды администратора сохраняются штатно.

## Камера чистки

CleaningPresentation.framing рассчитывает тесную перспективную рамку по вращающемуся bounding box, вместо сочетания независимых крайних точек большой сферы. Проверяются33положения полного переворота с запасом; сохраняются вертикальный ракурс, FOV50, место для прежних кнопок, плавный вход/выход и скрытие/восстановление крыши.

Проверка36находок ×5размеров экрана (1920×1080,1280×720,768×437,568×320,390×844),181положение и8углов: **180случаев/260640вершин,0обрезаний** в свободной области. Отношение расстояний к старой камере: min0,751/median0,825/max0,982; камера ближе примерно на2–25%, медиана17,5%. Расчёт не создаёт детали каждый кадр, выполняется при старте/изменении viewport.
