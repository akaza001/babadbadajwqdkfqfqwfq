# Навигация и переходы0.4.9

Продолжение по поручению пользователя «продолжи». Использован roblox-game-builder, существующая светлая тема WindowTheme и сохранённые компоненты0.4.7–0.4.8. Никаких новых растровых изображений/3D-моделей или изменений цен.

## Реализация

OnboardingUI: временный указатель теперь обычная GUI-плашка с проекцией мировой цели через Camera.WorldToScreenPoint. В исходной сессии BillboardGui имел корректные координаты/AbsoluteSize/onScreen, но не был виден на снимке; точная причина его рендера не установлена. Новый вариант реально виден. Он следует за целью/камерой, показывает направление при выходе цели из видимой области, ограничен свободной областью между боковыми кнопками и сужается на портретном экране. Два коротких текста, цвет общей темы, без перехвата ввода. Срок18с; новая цель отменяет старый таймер. Смена действия, скрытие обучения, удаление цели и уничтожение компонента очищают указатель/RenderStepped-соединение.

PortalWalkthrough: загрузка в общей теме, название озера назначения, неопределённый индикатор движения без выдуманного процента. Закрытие по серверному результату и при возрождении. Контроллер повторно не создаётся для одного Content; stop/Destroying отключают обработчики. При входе в арку во время cooldown или открытого меню попытка остаётся доступной после снятия ограничения: повторно выходить и входить не требуется. Отказ сервера по-прежнему требует нового входа и не запускает цикл запросов. Механика прохода безE сохранена.

## Что проверено

- Реальные клики Equip→Показать: указатель края помоста виден на игровом кадре768×437. Реальная цель портала содержит длинную подпись и помещается. Поворот управляемой камеры: front→обычная отметка, behind→ограниченная стрелка. Доказательства: navigation-049/waypoint.jpg, before.jpg и results.json.
-40 Frame-случаев обучения:10 состояний×4 размера1280×720,768×373,568×220,360×576.0 измеренных проблем TextFits/кнопок<44px.360 геометрических положений указателя (включая отрицательную глубину) внутри границ.16 сочетаний подписи/размера для самой плашки: TextFits и bounds прошли.
-36 Frame-случаев загрузки9 названий биомов×4 размера: названия/статусы помещаются, карточка внутри родителя. Повторный start возвращает тот же контроллер; повторный stop безопасен; пересоздание после stop и уничтожение host завершают контроллер.
- Старый timeout не уничтожил новую отметку: первая отметка17с, замена, ещё1.3с. Удаление цели очистило GUI. Тест Destroying проверяет результат после yield: синхронное ожидание удаления до обработки deferred-сигнала было ошибкой QA, исправлен только тест.
- Настройки открываются; в открытом меню указателя нет. Возрождение закрывает меню/загрузку; остаётся1HUD без отметки. Один mouse-tool применил открытие настроек, но не вернул завершение; его ожидание остановлено, фактическое состояние проверено через Studio. Production-ошибки в финальном Play не наблюдались.
- Автоматический вход вBIO-02 с магнитомII: реальный loading-screen показал «Ледяное озеро», сервер подтвердил прибытие, visitedBiomes записан, цель сменилась наtool3, загрузка закрылась. Снимок loading.jpg. С магнитомI: BIO-01 сохраняется, показан отказ оборудования2, loading=false.
- Быстрый вход в обратную арку до истечения клиентских3с: оставаясь внутри, игрок автоматически вернулся вBIO-01 после паузы; loading=false, посетилBIO-02=true. Ручной повторный вход не понадобился.
- Смерть с подтверждённым portalPending=true: Health=0→новый персонаж; после завершения BIO-01, portalPending=false, BIO-02 не отмечен посещённым, loading=false,1HUD. Ранняя попытка только с прямым LoadCharacterAsync дала неоднозначный результат гонки до смерти старого персонажа; окончательный случай проверен именно с Health=0.
- Новое поле visitedBiomes проверено облачно в отдельном MagnetWorkshopQA_v1:5 успешных проверок (default, запись, независимый writer/reload, legacy migration без изменения монет/настроек, malformed data без перезаписи). Только ключu:-40015, случайный scopeqa_n049a308efabe19d47ae9f7672010066bd6f. Ключ удалён, повторное uncached-чтение подтвердило0 данных. Реальные профили не затронуты. Исходники QA в navigation-049, не входят в runtime.
