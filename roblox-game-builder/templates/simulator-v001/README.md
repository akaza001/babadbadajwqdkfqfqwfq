# Simulator core 0.0.1

Отдельный стартовый шаблон, не копия существующей игры. Совместимый срез: собрать находку → инвентарь → продать → купить уровень. Конфиг задаёт предметы, цены, вместимость и уровни. Админ-команды работают только со своим профилем и по server allowlist. Это первая реализация ядра/установщика, не готовый полный симулятор.

**Данные RAM_ONLY: выход/остановка сервера сбрасывает прогресс.** DataStore, lease/конкурентные сессии, настоящие миграции старых игр, мир/базы/зоны, питомцы, Robux и публикация не реализованы. UI — функциональный прототип, без подтверждённой визуальной/мобильной приёмки. На экране постоянно указано отсутствие сохранений. Не использовать как production.

## Установка в новый тестовый проект

1. В Roblox Studio создай отдельный пустой place. Останови Play. Сохрани резервную копию тестового place.
2. Открой `dist/Install.luau`, скопируй весь файл в Studio Command Bar и выполни. Command Bar должен иметь право создавать Script.Source; не запускай установщик как обычный игровой Script/LocalScript. Файл не требует HTTP/плагинов/внешних mesh/image IDs и не публикует игру.
3. Установщик создаёт только три принадлежащих шаблону папки:
   - ReplicatedStorage.SimulatorTemplate — общие модули и Request RemoteFunction;
   - ServerScriptService.SimulatorTemplate — ядро, RAM-session adapter, AdminConfig, Bootstrap;
   - StarterPlayer.StarterPlayerScripts.SimulatorTemplate — Main LocalScript.
4. Нажми Play. В UI собери 4 находки, продай (20 монет), купи уровень 2. Теперь одно действие собирает 2 предмета. Проверь нехватку денег/полную вместимость.
5. Для админки в **серверном** AdminConfig добавь проверенный свой UserId: `userIds={[123456789]=true}` (число — пример, не реальные права). Запусти новый Play. Внизу панели появятся разрешённые команды и выдача по фактическому каталогу предметов. Reset требует второго действия подтверждения. Обычный игрок не должен иметь доступ даже прямым remote-запросом.

Установка не меняет Workspace, Lighting, DataStores или настройки существующей игры. Нет создаваемых поверхностей мира, поэтому материал мира здесь не назначается; GUI по политике исключён. UI использует утверждённую тему из библиотеки, но не вызывает иконки, требующие внешних IDs.

Повтор той же неизменённой установки ничего не меняет. Если хотя бы одна папка уже существует частично, версия другая или исходник вручную изменён, установщик отказывается перезаписывать. Исходники сначала строятся вне DataModel, runtime scripts включаются после привязки всех трёх папок. При ошибке удаляются только собственные созданные папки. Полное поведение прав/rollback в настоящей Studio ещё не проверено.

Для удаления останови Play и удали **только эти три папки** после сохранения полезных изменений. Автообновление существующей установки намеренно не реализовано. Следующую версию проверяй в другом пустом place.

## Контракты

- Config — schema 1, `items[id]={name,sell}`, `collectItem`, `upgrades={cost,yield}`, `coinsCap`, `capacity`, `currencyName`. Пример баланса не переносится как требование всех игр.
- Core.new(config,admin) — чистые функции defaults/validate/migrate/describe/apply. apply возвращает новую копию профиля либо nil,error; не изменяет исходный профиль при успехе или отказе. Клиент не выбирает награду collect. Новые предметы появляются в describe; новый тип характеристики требует отдельного обработчика и формы, произвольной записи путей/полей нет.
- Session.new(core,clock) — open/close/view/request. Профиль RAM; последовательные seq, 32 последних ответа, устаревшие seq отклоняются, rate limit 4 принятия/с. Повтор seq не применяет действие снова. После reconnect это новая сессия, не durable transaction ledger.
- Request: `{seq=positive_integer,action=string,args=flat_table}`. Actor определяется сервером по Player; target не принимается. Ответ `{ok,error?,profile?}`. describe отдельно возвращает каталог и разрешённые admin команды. Новая вкладка UI не создаёт права.
- Bootstrap — Roblox-адаптер жизненного цикла; Core/Session не знают game/Instance. Действия: collect/sell/upgrade; admin: coins.set/level.set/item.grant/progress.reset.
- Main — последовательный UI prototype; отображение по серверному ответу. Нет отмены таймаута InvokeServer/устойчивого клиентского retry-протокола. Перед production нужен асинхронный транспорт с ограниченным ожиданием/восстановлением состояния.

## Происхождение и зависимости

- `src/shared/WindowTheme.luau` и `HudIcons.luau` — точные копии magnet-ui-windows-v045, версия 0.4.5; require соседнего HudIcons сохранён. Используются поверхности, текст и кнопки темы; изображений UI-прототип не запрашивает.
- Идемпотентность, авторитет сервера, immutable snapshot и deny-all admin заимствуют инженерные контракты сохранённых пакетов magnet-biome-fishing-v048 и magnet-admin-panel-v056. Сам Core/Session/Bootstrap — **новая реализация**, а не копия их GameService/ProfileStore: старые модули зависят от MagnetWorld и исходной схемы. Их исторические cloud-проверки не переносятся на этот код.
- Ни реальные профили, ни исходные разрешения/данные игроков не включены.
- Runtime: Roblox services Players/ReplicatedStorage/ServerScriptService/StarterPlayer; никаких пакетов/ключей. Неизменённые модули темы сохранены рядом.
- Build: Python 3 стандартная библиотека. Test: `lupa` (LuaRuntime); временная установка зависимостей отдельно от runtime. Версия тестового окружения записана в tests/results.json.

## Сборка и проверка

Из этой папки:

```sh
python3 scripts/build.py
python3 tests/run.py
```

Для tests/run.py установи lupa в своё Python-окружение; использованная здесь временная среда: `PYTHONPATH=/tmp/roblox-template-deps`. Это не требование runtime/Studio. Builder создаёт Install.luau и manifest.json с точными SHA исходников. После изменения Config/AdminConfig в локальных файлах пересобери пакет перед новой установкой.

`tests/results.json` — реальные результаты локального запуска, не Roblox Play: транзакции/границы/права/дубликаты/отдельные профили, компиляция Lua-совместимого кода и установка в mock DataModel, отказ в Play/при частичной установке и откат при внедрённой ошибке создания. Следующий этап: чистая установка в Studio, реальные клики, respawn, адаптация маленького экрана и проверка runtime разрешений. Затем persistent storage adapter и изолированный cloud/rejoin QA; переносить RAM-слой в production нельзя.
