# Материал перед созданием объекта

Прямое общее указание пользователя, 11 ноября 2026: использовать приложенную текстуру на всех создаваемых объектах, кроме предметов, которыми игрок может пользоваться. Это новое общее пожелание для работы скилла, а не только стиль Fight for eggs.

Эталон: [square-relief-normal.png](../assets/materials/square-relief-normal.png). [Происхождение и SHA-256](../assets/materials/square-relief-normal.json). Изображение сохранено без изменения, независимо от временного clipboard-пути. По виду это tangent-space normal map: квадратный рельеф. Перед применением убедись, что направление рельефа соответствует ожиданию пользователя.

## Обязательный шаг до создания

1. Определи назначение создаваемого 3D-объекта: объект мира либо используемый игровой предмет.
2. Для объекта мира подготовь применение эталонного рельефа и добавь его в общий конструктор/шаблон, прежде чем массово создавать экземпляры. Пол, стены, здания, декор, стационарные модели и создаваемые существа не получают исключения автоматически.
3. Для используемых предметов сохрани собственный материал/текстуру. Примеры исключения: оружие, инструмент, удочка, магнит, расходник, подбираемый/переносимый предмет, который игрок экипирует или использует. Не покрывай его дочерние части общей картой только потому, что они BasePart.
4. Классифицируй по игровому назначению, не только по классу Tool или расположению в Workspace. Кнопка взаимодействия у двери/стационарного станка сама по себе не делает всю модель исключением. Если назначение ещё не определено, зафиксируй решение перед созданием материала; не назначай глобальную замену всем потомкам сцены.

Правило относится к видимым 3D-поверхностям. GUI, текст, иконки, изображения интерфейса, невидимые триггеры и хитбоксы не являются поверхностями для этой normal map. Не менять штатный аватар игрока массовым обходом его частей: здесь речь о создаваемых игровых объектах.

## Применение

Используй изображение как normal map, не как фиолетовый ColorMap/Decal. Сохраняй цвета, палитру и назначение физического материала. Шахматную окраску это правило не вводит: квадратный рельеф и цветной рисунок — разные слои.

Для повторяемого материала подходит MaterialVariant, для отдельного меша — совместимая SurfaceAppearance с проверенной UV-развёрткой. Наличие SurfaceAppearance у меша может перекрывать карты MaterialVariant: проверь фактический результат, а не только назначенное имя варианта. Актуальные свойства/права API сверяй перед реализацией по [Materials](https://create.roblox.com/docs/parts/materials), [MaterialVariant](https://create.roblox.com/docs/reference/engine/classes/MaterialVariant), [SurfaceAppearance](https://create.roblox.com/docs/reference/engine/classes/SurfaceAppearance). Документация проверена 2026-11-11.

У эталонного файла пока нет подтверждённого Roblox asset ID. При работе в игре найди уже доступный идентичный ассет или импортируй сохранённый PNG доступным разрешённым способом. Старый ID из другого проекта не считать этим изображением без проверки. Не выдумывай asset ID, не выдавай локальный путь за загруженную текстуру. Если импорт/доступ не выполнен, оставь явный статус «материал не применён».

Задавай согласованный масштаб и ориентацию плитки; не добавляй по физической детали на каждый квадрат. Сначала проверь один образец, затем покрывай нужную группу. Не меняй исходный PNG и не инвертируй каналы без установленной проблемы и сохранения оригинала.

## Проверка результата

- Объект мира: рельеф виден при подходящем свете, цвет/силуэт сохранены; на стыках нет наложения или несогласованной плитки.
- Используемый предмет: все его части сохраняют назначенное исключение при экипировке, переноске, выпадении и пересоздании.
- Шаблон/генератор и респавн воспроизводят правильный материал и исключения; повторное применение не накапливает overlays или дубли.
- Не назначай неизвестную текстуру при недоступном ассете и не называй результат проверенным без осмотра.

Текущий запрос обновляет правила скилла. Он не поручает автоматически перекрашивать уже существующие игры. При последующей работе новое явное указание пользователя об ином материале/исключении важнее этого значения по умолчанию; старые проектные правила согласуй с ним в затронутой области.
