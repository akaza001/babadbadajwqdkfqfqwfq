# Практические способы реализации

Это предлагаемые решения для собственных игр, не извлечённый код популярных игр. Выбирай способ под существующий проект; проверяй актуальные сигнатуры и ограничения в официальной документации. Рецепты ниже независимы от конкретного рейтинга.

Перед созданием моделей и окружения выполни [обязательный выбор материала и исключений](material-policy.md).

## Карта и окружение

Сначала блокаут масштаба персонажа: вход, безопасная зона, основной маршрут, точки интереса, возврат. Разделяй визуальные модели, физические препятствия и триггеры. Для биомов используй конфиги (палитра, набор декора, набор NPC/лут, требования входа), а не копии игрового кода. У моделей задавай pivot и стабильные ID, чтобы повторная сборка заменяла управляемую группу, не создавала дубли. Для процедурных комнат: seed, совместимые сокеты входов/выходов, проверка связности и аварийный выход. Для арены: дальность обзора, укрытия, маршруты без тупиков и безопасные точки спавна.

Проверка: реальный персонаж проходит все пути, NPC не застревает, спавн не внутри геометрии, декоративные детали не блокируют бой. Исследуй z-fighting, Decal/Texture, MaterialVariant, normal maps и стандартные поверхности отдельно; не меняй цвет, когда дефект вызван рельефом. У streaming-карты клиент не предполагает, что каждый объект уже загружен.

## UI

Опиши состояния экрана и источник данных до вёрстки. HUD показывает только нужное во время действия; каталог и инвентарь поддерживают поиск/фильтр, выделение, описание, вместимость и результат операции. Сервер возвращает подтверждённое состояние; кнопка не выдаёт предмет локально. Для окна покупки различай ожидание, успех, отказ и повторный запрос.

Используй адаптивные контейнеры, ограничения размеров, безопасные зоны и навигацию ввода, соответствующую выбранным устройствам. Проверяй короткий/длинный текст, русскую локализацию, маленький экран, пустой список, большой список, потерю соединения. Подробности: [UI](https://create.roblox.com/docs/ui), [input](https://create.roblox.com/docs/input).

## Предметы и инвентарь

Реестр определения: `typeId`, название, категория, модель, иконка, параметры, stackLimit. Экземпляр: уникальный ID, typeId, владелец, изменяемые параметры. Клиент отправляет ID действия/предмета; сервер проверяет владельца, состояние, дистанцию и лимиты. Операция списания/выдачи должна быть единой относительно серверного состояния, без окна для повторного запроса. Не сохраняй Instance в профиле: сериализуй ID и данные. Для получения награды используй ключ операции, чтобы повтор не дублировал выдачу.

Иконки строй из собственных моделей в одинаковом ракурсе/свете либо создавай отдельно; проверяй читаемость на размере UI. Не загружай чужой ассет из игры без прав.

## Животные, питомцы и NPC

Раздели species-конфиг, визуальную модель и экземпляр питомца игрока. Конфиг: масштаб, риг, набор анимаций, редкость, способности, биом, иконка. Сначала согласуй силуэт и пропорции с двух ракурсов, затем pivot, точки контакта с землёй и коллизии. Для quadruped не подставляй человеческие оси суставов без проверки.

Состояния: idle, follow/move, action, stunned/dead по необходимости. Сервер управляет владением и игровым эффектом; визуальное следование может рассчитываться клиентом, если оно косметическое. Разнеси позиции группы питомцев и ограничь частоту тяжёлых расчётов. Для физического NPC проверь препятствия и восстановление после неудачного пути. При hatch сервер выбирает результат, проверяет валюту/вместимость и сохраняет приобретение; вероятность/торговлю/платные случайные предметы проверяй по действующим правилам Roblox.

## Риг и анимации

Выбери скелет MeshPart с bones либо сборную модель с Motor6D под нужный экспорт/редактор. Сохрани исходную позу и оси; проверь pivot и суставы до клипов. Набор движения: idle, walk/run, действие, реакция/смерть по задаче. Клипы должны соответствовать ригу. Не считай auto setup humanoid универсальным риггером животных.

Idle не проигрывает шаги; скорость цикла согласуется с перемещением; остановка возвращает idle. Проверяй приоритеты, loop и переходы: атака не блокирует движение навсегда. Для процедурного движения сохраняй базовые transforms и сбрасывай их при завершении. Проверяй контакт ног и высоту корня во всех крайних позах; крылатый полёт — отдельное состояние. Обновляй и шаблон респавна, не только текущего NPC.

Источники: [Animation Editor](https://create.roblox.com/docs/animation/editor), [Rigging](https://create.roblox.com/docs/art/modeling/rigging). На 2026-11-06 подтверждены работа редактора с ригами и возможность построения скелета во внешнем 3D-редакторе; точные права публикации проверять в целевом проекте.

## Бой и поведение

Серверная машина состояний: поиск/сближение → подготовка → активный удар → восстановление. Явно задай дальность, направление, длительность и кулдаун. Телеграф соответствует фактическому окну и зоне урона. Разделяй боевой hitbox и декоративную геометрию. Проверяй повторное попадание в одной атаке, смерть цели, выход игрока и респавн босса. Воздушный босс остаётся достижимым согласованными способами атаки.

## Сеть, сохранения и покупки

Опиши payload каждого RemoteEvent, разрешённые состояния, частоту, диапазоны и серверные проверки; недоверенный клиент не задаёт сумму награды. Отсутствие визуального эффекта не отменяет серверную проверку. [Граница клиент-сервер](https://create.roblox.com/docs/scripting/security/client-server-boundary).

Профиль имеет версию схемы, значения по умолчанию, миграции и проверку сериализуемости. Проверь ошибки записи и одновременные сессии согласно выбранной библиотеке профилей. Не обещай надёжность без проверки реального жизненного цикла. Для продукта выдача привязана к серверному receipt и защите от повтора; клиентское закрытие окна покупки не доказывает оплату. [Data stores](https://create.roblox.com/docs/cloud-services/data-stores), [MarketplaceService](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService).

## Производительность и готовность

Сначала измеряй узкое место; общая цель — стабильное выполнение на целевом устройстве, а не произвольное число деталей. Переиспользуй эффекты, очищай соединения и временные объекты, не запускай отдельный тяжёлый Heartbeat на каждую частицу/питомца. Для массовых NPC/коллекций измеряй худшую ожидаемую сцену. Заверши плейтестом выбранного среза с несколькими клиентами при сетевых взаимодействиях. [MicroProfiler](https://create.roblox.com/docs/performance-optimization/microprofiler).
